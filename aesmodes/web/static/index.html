§1What AES does

AES is a block cipher: it takes exactly 16 bytes (128 bits) of plaintext and a key, and produces 16 bytes of ciphertext. The bytes are arranged in a 4 × 4 grid called the state, and the same four operations are applied round after round:

The block is always 128 bits. The key can have three lengths, and a longer key means more rounds:

variantkeyrounds Nrkey words
AES-12816 bytes1044
AES-19224 bytes1252
AES-25632 bytes1460

Each operation has a job. SubBytes adds confusion, meaning a non-linear relation between key and ciphertext. ShiftRows and MixColumns add diffusion, spreading every input bit over the whole block. AddRoundKey mixes in the secret key.

§2Why we need modes

A real message is longer than 16 bytes. A mode of operation is the recipe for cutting a message into blocks and connecting them:

  • ECB encrypts every block separately
  • CBC XORs each block with the previous ciphertext first
  • CFB encrypts the previous ciphertext and XORs the result
  • OFB keeps encrypting its own output to make a keystream
  • CTR encrypts a counter to make a keystream
Project specification. Implement AES in 5 modes: ECB, CBC, CFB, OFB, and Counter mode where the user will set the initial counter value (padding of last block should be done with zeroes along with count of pad size; Initial vectors should be set to zeroes).

4.1The ECB picture problem

An image is just bytes. Below, the same picture is encrypted with each mode, and the encrypted bytes are drawn back as pixels. ECB turns equal 16-byte blocks into equal ciphertext blocks, so large areas of one color keep their shape. The other modes chain or randomize the blocks, so you only see noise.
