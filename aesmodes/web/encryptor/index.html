How it works

Our own AES

AES-128/192/256 and the five modes come from the project's Python code (aes_core.py, modes.py, and a table-based fast path in fastaes.py), checked against the official FIPS-197 and NIST SP 800-38A test values.

Runs in your browser

The Python code runs inside this page with Pyodide (Python compiled to WebAssembly), in a background worker. Your files and passwords never leave your computer.

Password → key

Passwords are stretched into an AES key with PBKDF2-HMAC-SHA256 and a random salt, so the same password gives a different key each time.

Tamper check

An HMAC-SHA256 tag covers the whole file, so a wrong password or any changed byte is detected before decryption.

Self-describing files

The .aesm format stores the mode, key size, IV or counter, salt and original file name. To decrypt you only need the password or key.

Padding

As in the project specification: zero bytes plus one byte holding the pad count. CBC/CFB/OFB default to a zero IV, as the specification asks.

Built for a university course. It's educational software: for protecting truly sensitive data, use an established tool such as age, GnuPG or your operating system's disk encryption.
